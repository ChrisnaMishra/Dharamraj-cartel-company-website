# Security Policy

Thank you for helping keep Dharamraj Cartel and its visitors safe.

## Reporting a vulnerability
**Do not publish exploit details, credentials, tokens, private customer information, or a working attack in a public Issue.**

Preferred method: use GitHub's **Report a vulnerability** option in the repository's **Security → Advisories** area if private vulnerability reporting is enabled.

If that option is not available, open a brief public Issue titled **"Request for private security contact"** without technical details or proof of concept. Ask the maintainer for a private reporting route. Do not include vulnerability details in that Issue.

The repository owner should enable GitHub private vulnerability reporting in **Settings → Security and quality → Advanced Security → Private vulnerability reporting**, where available.

When reporting privately, include the affected page or file, the potential impact, reproduction steps and a suggested fix if known. Please allow reasonable time for review before public disclosure.

## Scope
This repository contains a static website and client-side code. Do not access accounts, systems or information that do not belong to you; do not test against real customer data; and do not perform destructive or disruptive testing.

## Secrets and credentials
Never add credentials, API keys, tokens, passwords, database strings, private customer details or confidential supplier information to source code, Issues or Pull Requests. If a secret is exposed, rotate or revoke it immediately; deleting it from the latest file alone may not remove it from Git history.

## Response
The maintainer will review reports as time allows and may ask for clarification. This policy does not promise a particular response time.
